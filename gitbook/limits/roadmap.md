# 로드맵

> **이 문서의 「단계」는 GASOK 심사의 Phase 1·2와 무관하다.** 개발 일정이다.
> 현재 구현 상태는 [하지 못한 것](not-done.md)에 있다.

## 무엇이 이 로드맵을 무너뜨리나

| | |
|---|---|
| 사람들이 판단을 반복해서 남기지 않으면 | 이후 전부가 의미 없어진다. 콜드스타트 문제가 첫 검증 대상이다 |
| POI 쪽 오라클(Phase 2)이 안 나오면 | 정산은 계속 소유자 제출이다. 마루의 「활성 정산」 필터는 등록 여부 이상을 주장하지 못한다 |
| GIWA 월렛 임베드 규격이 안 열리면 | [월렛 탑재 가능성](../giwa/wallet.md)의 넷은 계속 질문으로 남는다 |
| 보자기(GIWA 영지식) 문서가 안 나오면 | 봉인 판단은 시작할 수 없다. 다만 마루는 여기 **의존하지 않는다.** 지금 형태로 계속 돈다 |

## 순서

### 1단계: 자체 구현. 막는 것이 없다

- 코멘트 인증, 온체인 팔로우: 새 EAS 스키마가 필요하지만 외부 의존은 없다
- REASON 재사용(replay) 방어: 커밋 프리이미지에 결정 UID·부모를 묶는 설계 검토
- 필터 확장: 지금은 도장 검증·활성 정산 둘뿐이다
- 자격제 방: 도장 Verified Balance의 머클 포함 증명으로 「보유 ≥ X」를 원장 공개 없이
  증명한 사람만 보이는 방. **보자기를 기다릴 필요가 없다** — 이미 온체인에 있는 기능이다.
  남은 확인은 도장 스냅샷 발급 주기뿐이다

### 2단계: 외부 의존이 시작된다

POI의 Phase 2(Upbit Oracle, `ORACLE_VERIFIED`, Verified Balance 배지)가
붙으면 마루도 그 위에서 갱신된다.

| 항목 | 마루에서 무엇이 달라지나 |
|---|---|
| `ORACLE_VERIFIED` | 「활성 정산 있음」 필터가 「독립 판정됨」으로 강화될 수 있다 |
| Verified Balance 배지 | 잔고를 밝히지 않고 포지션 보유를 증명하는 배지를 프로필에 붙일 수 있다 |
| Execution 경로 | 「말한 대로 했나」까지 화면에서 대조할 수 있다 |

**이것은 가설이다.** 거래소가 읽기 권한을 열지, POI 쪽 오라클 사양이
언제 나올지 확정된 것이 없다.

### 3단계: 보자기 — 봉인 판단

이 제품의 가장 큰 채택 장벽은 구조에 있다. **먼저 공개해야 나중에 증명되는데,
먼저 공개하면 자기 판단의 값어치를 남에게 준다.** 실력 있는 사람일수록 안 올린다.

영지식 증명은 여기를 정확히 푼다. **봉인은 공개하고 내용만 가린다.**

| | |
|---|---|
| 지금 | 이유 원문은 salted commitment — 해시를 먼저 올리고 나중에 원문을 공개한다. **열어야 증명된다** |
| 보자기 이후 | 조건 자체를 가린 채 발행하고, 구간이 끝나면 「맞음」만 증명한다. **안 열고도 증명된다** |
| 그 다음 | 「봉인 12건 중 8건 맞음」처럼 **분모까지** 증명한다 |

분모 증명이 중요한 이유가 따로 있다. 지금 순위·집계를 만들지 않은 까닭이
「공개된 기록만 세면 안 올린 판단이 빠져 편향된다」인데
([소셜 문제](../problem/sns.md)), 분모가 증명되면 그 편향이 사라진다.
**보자기는 새 기능 하나가 아니라, 이미 막혀 있던 항목을 푸는 열쇠다.**

카드가 사라지지도 않는다. 시각·발행자·도장·관측 구간은 그대로 뜨고 조건만 가려진다.
구간이 끝나면 열린다.

막고 있는 것: **보자기 개발자 문서.** `docs.giwa.io/giwa-ecosystem/bojagi`는
2026-07-30 기준 404이고 생태계 목록에도 없다. POI의 `predicate`가
`metricId · op · threshold` 구조라 ZK 술어와 모양이 같아, 공개되면 적용 비용은 작다고 본다.
**규격을 모르는 채 만들면 추측이 코드가 된다.**

### 4단계: 월렛 탑재

[월렛 탑재 가능성](../giwa/wallet.md)에 남은 질문 넷의 답을 받으면 manifest·SDK
adapter를 만든다. 규격을 모르는 채 만들면 추측이 코드가 된다.

## 그 위에 무엇이 올라갈 수 있나

검증된 판단이 쌓이면 그 위에 제품이 올라간다. 아래는 **배포된 컨트랙트를
읽기만 하면 되는 것들**이라 새 온체인 구조가 필요하지 않다는 뜻이지,
**만들었다는 뜻이 아니다. 전부 미구현이다.**

| | 무엇 | 무엇으로 되나 |
|---|---|---|
| 조건부 커뮤니티 | 「활성 정산 N건 이상」인 사람만 보는 방 | 지금 필터의 확장 |
| B2B 신뢰도 부착 | 리서치 발행물에 검증 링크 | POI 외부 조회 API(POI 로드맵 3단계) |
| 지갑 내 알림 | 팔로우한 판단의 결과가 나오면 알림 | 월렛 탑재 이후 |
| 익명 지속 신원 | 지갑은 감추되 「같은 저자」·「도장 검증됨」은 증명 | 보자기 + 별칭 정책 |
