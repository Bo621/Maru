# 입장 변경 이력

결정에는 `parents`가 있다. 마루는 `parents[0]`을 따라 올라가며 스레드를
조립한다. 이건 **타인에게 다는 답글이 아니라 한 지갑이 입장을 바꾼 이력**이다.

## 왜 답글이 아닌가: 컨트랙트가 그렇게 강제한다

POI 컨트랙트는 "같은 지갑의, 더 이른, 살아 있는 결정만 부모가 될 수 있다"를
강제한다. 타인의 결정을 부모로 지정하면 트랜잭션이 되돌아간다. 그래서 화면
문구는 "이전 판단"이지 "답글"이 아니다. `refUID == parents[0]` 불변식이
있으므로 `parents[0]`을 스레드 부모로 삼는다.

## 조립 규칙(`src/thread.ts`)

```ts
export interface ThreadNode {
    uid: Hex;
    depth: number;      // 0이 시작 결정, 커질수록 더 이른 판단
    resolved: boolean;   // 체인에서 읽어온 결정인지
}
```

컨트랙트 불변식상 순환은 불가능하지만, 조회 계층이 깨져도 무한 루프에
빠지지 않도록 최대 깊이(16)와 방문 집합을 둔다. **원리적으로 불가능한
것과 조회 코드가 항상 안전한 것은 다르다.** 후자를 별도로 보장한다.

## 부모 조회 실패는 그대로 남긴다

조회하지 못한 부모를 목록에서 빼지 않는다. `feedData.ts`가 실패한 UID를
숨기지 않는 정책과 같다. 화면은 "부모를 불러오지 못했습니다 — `<uid>`"를
그대로 보여준다. 조용히 빼면 「조회된 것이 전부가 아니다」라는 이 제품의
다른 주장과 모순된다.

## 화면

결정 상세에 스레드 노드가 2개 이상일 때만 섹션이 나타난다(1개, 즉 부모가
없으면 표시하지 않는다). 각 항목은 부모 결정으로 링크되고, 조회 실패는
그 자리에 남는다.
