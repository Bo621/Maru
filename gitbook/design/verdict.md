# 맞고 틀림: 업비트 재계산

피드와 결정 상세는 관측이 끝난 결정에 맞음·틀림을 붙인다. **이 판정은 화면이
업비트 1분봉으로 다시 계산한 것이지 온체인 기록이 아니다.** 온체인에는
관측값과 그로부터 산술로 도출된 `result`만 있고, 「맞았다/틀렸다」라는
사람이 읽는 판정은 마루가 화면에서 만든다.

## 규칙은 한 곳(`src/verdict.ts`)에만 있다

```ts
export type Verdict =
    | {kind: "match"; observed: string}
    | {kind: "mismatch"; observed: string}
    | {kind: "pending"}          // 관측 구간이 아직 안 끝났다
    | {kind: "notApplicable"}    // 예상 결과를 선언하지 않은 결정
    | {kind: "unsupportedMetric"}// 업비트 1분봉 종가로 판정할 수 없는 지표
    | {kind: "unobserved"};      // 창 안에 쓸 수 있는 봉이 없다
```

비교는 `@poi/core`의 `evalPredicate`만 쓴다. 여기서 분기를 새로 쓰면
컨트랙트와 같은 술어 계산을 화면이 다시 만들다 어긋날 수 있다. `decideVerdict`는
지표 가드를 먼저 본다. `BTC_PRICE_KRW_AT_END`가 아닌 지표에 종가를 들이대면
자신 있게 틀린 판정을 낼 수 있기 때문이다.

## 관측값을 고르는 규칙

`pickObservedClose`는 verifier와 같은 규칙을 쓴다. **창 안에서 시작하고
창 종료까지 완전히 닫힌 봉만** 쓰고, 그중 마지막 것의 종가를 쓴다. 규칙이
갈라지면 화면과 검증기가 다른 값을 말하게 된다.

```
관측 여유(OBSERVATION_LAG) = 120초
```

창이 끝난 직후 바로 판정하지 않고 120초를 기다린다. 체인 시각이 실제 시각보다
앞서거나 업비트 봉 발행이 늦으면, 아직 확정 안 된 봉을 읽을 수 있어서다.

## 빌드 시점 스냅샷: 왜 필요한가

배포 출처(Railway)에서는 업비트 API 요청이 대부분 막힌다(`Failed to fetch`).
**닫힌 관측 구간의 값은 불변**이므로, 빌드 시점에 미리 계산해
`public/verdicts.json`에 담아 둔다.

```json
{
  "version": "maru.verdict-snapshot.v1",
  "observed": {
    "<decisionUID>": {"startedAt": "1785343260", "close": "91727000"}
  }
}
```

담는 것은 **판정이 아니라 관측에 쓴 봉 하나**다. `decideVerdict`는 여전히
이 봉으로 술어를 계산한다. 스냅샷이 판정 자체를 담으면 규칙이 두 곳으로
갈라진다. 스냅샷의 상세는 [판정 관측값 스냅샷](snapshot.md)에 있다.

## 재시도는 필요한 것만

`planNextAttempt`는 조회 실패만 고정 간격(30초)으로 재시도한다. 관측 불가
(창에 겹치는 봉이 없음)는 영구 조건이라 다시 물어도 답이 같아서 재시도
대상에서 뺀다. 아직 이른 결정은 정확히 그 시각(`windowEnd + 120초`)에 맞춰
깨운다. `setTimeout`의 32비트 상한(약 24.85일)을 넘기지 않도록 지연을
bigint 단계에서 자른다. 자르지 않으면 오버플로해서 거의 즉시 실행돼,
루프를 막으려던 코드가 루프를 만든다.

## 화면에 반드시 붙는 문구

```
판정은 업비트 1분봉으로 다시 계산한 결과입니다. 관측이 끝난 구간은 배포
시점에 계산해 담아 둔 값이고, 새로 끝난 구간은 이 화면이 조회합니다.
온체인에 기록된 판정이 아닙니다.
```

문구의 「새로 끝난 구간은 이 화면이 조회합니다」는 시도한다는 뜻이지 항상
성공한다는 뜻이 아니다. 업비트가 브라우저 Origin 요청을 10초당 1회로
제한해, 배포 환경에서는 바로 뜨지 않을 수 있다. 자세한 실측은
[판정 관측값 스냅샷](snapshot.md)에 있다.

이 판정이 무엇을 증명하고 무엇을 증명하지 않는지는
[무엇이 증명되고 무엇이 안 되나](../problem/what-is-proven.md)에서 다시 다룬다.
