# 심사 시나리오 S1~S12

지원서에 그대로 넣은 시나리오다. **S1~S10은 지갑 없이 된다.** 작성(S11~S12)만
지갑이 필요하다. 전부 `e2e/feed.spec.ts`로 GIWA Sepolia를 상대로 고정돼 있다.

## 읽기: 지갑 없이

```
S1  /#/feed 를 연다
    → 여러 지갑의 결정이 시간 역순으로 나열된다
    → 「순위가 아닙니다」·「조회된 것이 전부라는 보장은 없습니다」가 보인다

S2  「도장 검증 지갑만」을 켠다
    → 검증 스냅샷이 붙은 결정만 남는다
    → 각 줄에 「도장 검증 — TESTNET FAUCET」 라벨이 보인다

S3  「발행자별 활성 정산 최소 건수」를 올린다
    → 정산이 적은 발행자가 사라진다
    → 필터는 발행자 단위다: 통과한 발행자의 미정산 결정은 그대로 남는다
      (미발행도 그대로 보인다)

S4  URL 을 복사해 새 창에 붙인다
    → 같은 필터가 유지된다 (조건부 커뮤니티 링크)

S5  발행자를 누른다 → 발행자별 기록 → 결정 상세 → 「검증하기」
    → 오프체인 재현까지 이어진다

S6  스레드 배지가 붙은 결정을 누른다
    → 같은 지갑이 앞서 올린 판단으로 이어진다 (parents DAG = 입장 변경 이력)

S7  이유 원문이 인용 블록으로 보이고, 해시가 맞는 것에만 일치 표시가 붙는다
    → 파일을 고치면 표시가 사라진다 (원문은 커밋의 증거지, 커밋이 원문을 만들지 않는다)

S8  관측이 끝난 결정에 판정이 붙는다
    → 업비트 1분봉으로 재계산한 맞음·틀림이 함께 나온다
    → 틀린 것도 그대로 나온다

S9  첫 줄의 팔로우를 누르고 「팔로우」 탭으로 간다
    → 그 지갑의 판단만 남는다
    → 「이 브라우저에만 저장됩니다」 고지가 보인다 (온체인 팔로우가 아니다)

S10 「곧 결과 나옴」 탭을 연다
    → 아직 창이 안 닫힌 판단이 마감 임박 순으로 뜬다
    → 결과를 기다리는 상태가 그대로 보인다
```

## 쓰기: 지갑 필요 (GIWA Sepolia)

```
S11 지갑 없이 「판단 발행」을 연다
    → 연결 안내가 뜬다 (막다른 길 대신 안내로 이어진다)

S12 지갑을 연결하고 판단을 올린다
    → 관측 구간은 분 경계로 정렬되고, 지난 구간은 거부된다
    → 서명하면 피드 맨 위에 뜨고, 창이 닫히면 판정이 붙는다
```

**S12가 이 제품의 핵심이다.** 결과를 알기 전에 고정하는 것 말고는 올릴
방법이 없다.

## E2E가 시나리오 이름과 실제로 같은 것을 검사하는가

시나리오 이름과 테스트의 단언이 어긋나면 시딩한 데이터가 제품 서사를
깨도 초록색으로 남는다. 그래서 `e2e/feed.spec.ts`는 각 시나리오에 **행 수가
실제로 줄어드는지, 발행자 집합이 실제로 좁혀지는지**까지 기준선(필터 없는
상태) 대비로 확인한다. "필터를 지웠을 때 테스트가 깨지지 않으면 그 테스트는
무의미하다"는 원칙을 E2E에도 적용한다.

```
S1  결정 행 수 ≠ 0, 고유 발행자 수 ≥ 2, data-block-number 내림차순
S2  verified=1 적용 후 결정 행 수 < 기준선 결정 행 수 (오류 행은 빼고 센다)
S3  match≥1을 기준선에서 적용했을 때 고유 발행자 수 < 기준선 발행자 수
```

S2 위에서 S3을 재면 안 된다. S2가 미검증 지갑을 전부 걷어내면 검증된
발행자 하나만 남고, 그 발행자는 활성 정산을 갖고 있어 S3가 아무것도 줄이지
못한다. 그래서 S3 보강은 필터 없는 피드 대비로 별도 테스트에 있다.
