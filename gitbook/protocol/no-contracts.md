# 새 컨트랙트 0개

마루는 이번 범위에서 **컨트랙트를 하나도 배포하지 않는다.** 저장소에
`contracts/` 디렉터리 자체가 없다.

## 왜: 컨트랙트 재배포는 POI 쪽에서도 비용이 크다

POI 쪽에서 컨트랙트를 한 번 수정·재배포할 때마다 fixture 재생성, 문서
전수 갱신, 2-of-2 Safe 승인이 따라왔다. 마감이 다가온 시점에 마루가
같은 비용을 또 지불할 이유가 없다. 프론트만으로 소셜 표면이 충분히 선다는
것을 아래 표로 확인했다.

## 표 전체에서 새 컨트랙트가 필요한 칸은 둘뿐이다

| 소셜 기능 | 무엇으로 되나 | 새 컨트랙트 |
|---|---|---|
| 피드: 검증된 판단이 흐른다 | `readDecisionLogs` + 상태 판정 | 불필요 |
| 작성: 판단을 올린다 | 기존 decision 스키마에 attest | 불필요 |
| 프로필: 그 사람의 기록 | 발행자 주소로 필터링한 같은 로그 조회 | 불필요 |
| 팔로우 | 브라우저 로컬 저장 | 불필요, 온체인이 아니라고 밝힌다 |
| 맞음·틀림 | 업비트 1분봉으로 재계산 | 불필요 |
| 이유 원문 | 공개 파일의 salt·payload로 커밋 재계산 | 불필요 |
| 입장 변경 이력 | `parents` DAG | 불필요 |
| 조건부 열람 | 발행자별 활성 정산 건수로 필터 | 불필요 |
| 인증 배지: 도장 라벨 | `issuerLabel` 이미 읽는 중 | 불필요 |
| 코멘트 인증 | 새 스키마·리졸버 | **필요, 이번엔 안 한다** |
| 온체인 팔로우 | 새 스키마 | **필요, 이번엔 안 한다** |

**둘 다 이번 범위 밖이다.** 소셜 표면은 이미 배포된 POI 컨트랙트를 읽고
쓰는 것만으로 선다. 코멘트 인증과 온체인 팔로우를 만들지 않기로 한 이유는
[하지 못한 것](../limits/not-done.md)에 있다.

## 마루가 쓰는 것: 읽기와 쓰기 둘 다 기존 스키마로

- **읽기**: `readDecisionLogs`가 EAS 로그를 청크로 읽고, `readDecision`이
  스키마 UID를 검사해(`assertSchema`) 다른 스키마의 attestation을 걸러낸다.
- **쓰기**: 판단 발행(`#/write`)은 사용자 지갑이 기존 decision 스키마에
  직접 attest한다. 마루 서버가 대신 서명하지 않는다. 서버 자체가 없다.

주소·스키마 UID는 [배포와 주소](../intro/deployed.md)에 있다.
