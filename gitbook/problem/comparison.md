# 일반 SNS · POI · 마루 비교

세 층이 하는 일은 서로 다르다. 여러 문서에 흩어져 있던 구분을 한 표로
모은다.

| | 일반 SNS(트위터 등) | POI 프로토콜 | 마루 |
|---|---|---|---|
| 무엇을 다루나 | 아무 글이나 자유 형식 | 조건·관측 구간·정산을 온체인 attestation으로 | POI의 attestation을 읽어 소셜 표면으로 보여줌 |
| 사후 편집 막기 | 못 막는다(글 수정·삭제 가능) | 결정은 철회도 재작성도 안 됨(`revocable=false`), 정산만 철회 가능하고 철회 시 이력을 대체함 | POI가 막은 것을 그대로 보여줌(새로 막지 않음) |
| 선택적 공개 막기 | 못 막는다 | 발행 뒤 정산 미등록은 「기한초과」로 컨트랙트에 남음(애초에 미발행인 것은 알 수 없음) | 「조회된 것이 전부라는 보장은 없다」고 명시, 필터를 통과한 발행자의 미정산 결정은 숨기지 않음 |
| 수익률·거래 실행 검증 | 안 함 | 안 함(조건 충족 여부만 산술 계산) | 안 함 |
| 사람이 읽는 진입점 | 있음 | 있음 — [공개 화면](https://vestat.gitbook.io/poi/usage/screens)에서 결정 한 건을 열고 발행·검증한다 | 있음 — 여러 발행자를 한 줄로 모아 본다 |
| 탐색 단위 | 글 한 개 | **결정 한 건** — UID를 알고 들어간다 | **사람** — 발행자를 팔로우하고 시간 역순으로 훑는다 |
| 반복해서 하는 행동 | 읽고 쓴다 | 발행하고 검증한다 | 팔로우한 사람의 결과가 갈릴 때 다시 온다 |
| 새 컨트랙트 | 해당 없음 | POI가 배포 | **0개, POI 스키마만 읽고 씀** |

**마루의 자리는 셋째 열이다.** POI가 증명하는 것 위에 새로 증명하는 것은
없다. 차이는 화면의 유무가 아니라 **탐색 단위**에 있다. POI는 결정 한 건을
깊이 파고, 마루는 여러 발행자를 얕게 훑는다. 전자는 UID를 이미 아는 사람의
도구이고, 후자는 **누구를 볼지부터 고르는** 사람의 화면이다. 자세한
근거는 [무엇이 증명되고 무엇이 안 되나](what-is-proven.md)에 있다.
