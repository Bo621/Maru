# SNS의 최소 조건

증명 레이어가 있다고 소셜 제품이 되는 것은 아니다. 마루가 최소로 갖춰야 했던 것 넷.

## 1. 흐름 — 목록이 아니라 여러 사람의 판단

피드는 한 결정을 깊게 보여주는 화면이 아니라, 여러 지갑의 결정이 시간 역순으로
지나가는 화면이다. 단위 화면(결정 상세)은 이미 POI에 있다 — 마루는 그걸
다시 만들지 않고 "열기" 링크로 잇는다.

## 2. 사람 — 프로필이 있어야 「이 사람의 판단」이 성립한다

`#/p/<address>`는 한 지갑의 판단만 시간순으로 모은다. 승률·수익률·건수 집계는
만들지 않는다 — 선택 기록으로 순위를 만들면 그 자체가 거짓말이다
([설계 원칙](../design/screens.md) 참고).

## 3. 링크로 보낼 수 있는 조건 — 「걸러진 방」

필터 상태가 URL 쿼리에 실린다. 「이 조건에 맞는 사람만 보이는 방」을 링크
하나로 보낼 수 있어야 커뮤니티의 최소 형태가 된다. 자세한 필터 규칙은
[화면 구조와 라우팅](../design/screens.md)에 있다.

## 4. 관계 — 팔로우와 스레드

팔로우는 「내 피드」를 만들고, 입장 변경 이력(스레드)은 「이 사람이 생각을
바꾼 기록」을 보여준다. 둘 다 온체인 증명이 필요한 기능이 아니라서 이번
범위에 들어갔다 — 팔로우는 로컬 저장([팔로우와 탭](../design/follow.md)),
스레드는 컨트랙트가 이미 강제하는 부모-자식 관계를 읽기만 한다
([입장 변경 이력](../design/thread.md)).

## 의도적으로 뺀 것

좋아요, 댓글, 온체인 팔로우, 코멘트 인증 — 전부 새 스키마나 온체인 근거가
필요하다. 이번 범위 밖이다. 자세한 이유는 [하지 못한 것](../limits/not-done.md)에 있다.
