# 마루의 신뢰 경계

마루는 새 증명 레이어가 아니다. **온체인 기록 · 오프체인 시세 · 공개 파일 ·
브라우저 설정**을 한 화면에 모으는데, 이 넷은 근거의 강도가 서로 다르다.
같은 카드 안에 나란히 붙어 있어서 한 덩어리로 보이지만 아니다.

## 화면에 있는 것의 출처

| 출처 | 마루가 쓰는 것 | 주의할 것 |
|---|---|---|
| **결정 어테스테이션** (GIWA Sepolia) | 발행자 · 발행 시각 · 조건 · 관측 구간 · 이유 커밋 | 마루가 이 기록을 바꾸지는 못한다. 다만 **RPC 조회가 전부를 돌려줬다는 보장은 없다** |
| **정산 리졸버** | 활성 정산 · 철회 이력 | 정산은 **결정 소유자가 제출**한다. 컨트랙트는 산술만 검사하고 **관측값 자체의 진실성은 검사하지 않는다** |
| **업비트 1분봉 · `verdicts.json`** | 화면의 맞음·틀림 | **온체인 기록이 아니다.** 이 화면이 방금 계산한 값이다 — [판정](../design/verdict.md) |
| **`public/reveals/*.json`** | 이유 원문의 salt와 payload | 커밋 해시와 맞을 때만 표시한다. **해시 일치는 문장이 참이라는 뜻이 아니다** — [해시 대조](../design/reason.md) |
| **브라우저 로컬 저장** | 팔로우 목록 | **온체인 관계가 아니다.** 브라우저를 지우면 사라진다 — [팔로우와 탭](../design/follow.md) |
| **POI 검증기** | 관측값 재계산 후 등록된 정산과 대조 | `MATCH`는 **「등록된 관측값이 재계산과 같다」**지 예측이 맞았다는 뜻이 아니다 — [검증기로 잇기](../verify/cli.md) |

## 이 넷이 서로를 대신하지 않는다

화면에 나란히 붙는 네 가지 표시는 **각각 다른 질문**에 답한다.

| 표시 | 답하는 질문 |
|---|---|
| 도장 검증 라벨 | 이 지갑이 사람 확인을 거쳤나 |
| 이유 해시 일치 | 이 문장이 결과 전에 잠겼던 그 문장인가 |
| 화면 재계산 맞음·틀림 | 선언한 조건이 관측 구간에서 충족됐나 |
| 검증기 `MATCH` | 온체인에 등록된 관측값이 다시 계산한 값과 같은가 |

**하나가 참이라고 나머지가 참이 되지 않는다.** 도장 검증된 지갑이 틀린 판단을
할 수 있고, 화면이 「틀림」으로 표시한 결정도 검증기에서는 `MATCH`가 나온다.
그래서 화면은 이 넷을 한 배지로 합치지 않는다.

## 마루가 보장하지 않는 것

- **실사용자·활성도** — 없다. 피드의 기록은 시연용 데모 페르소나다
- **관측값 자체의 진실성** — 업비트가 준 값을 그대로 쓴다
- **조회된 기록의 완전성** — 「조회된 것이 전부라는 보장은 없다」고 화면에 적어 두었다
- **애초에 발행하지 않은 판단** — 어디에도 남지 않으므로 알 수 없다
- **실제 거래 실행** — 「말한 대로 했나」는 다루지 않는다

마지막 둘이 이 제품의 근본 한계다. **온체인에 올라온 것만 다룬다.**
자세한 내용은 [무엇이 증명되고 무엇이 안 되나](what-is-proven.md)와
[하지 못한 것](../limits/not-done.md)에 있다.

> [POI 백서의 신뢰 경계](https://vestat.gitbook.io/poi/problem/trust-boundary)에
> 더 자세히 있다. 위 표는 **마루 화면에 실제로 뜨는 것**만 다룬다.
